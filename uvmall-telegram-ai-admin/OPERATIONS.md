# UVMALL AI — оперативная инструкция

## Что реализовано

- Команды менеджера в @uv_mallbot (доступ только Telegram ID 8771756849): /panel, /tickets, /stats, /reply ID текст, /close ID, /resolve ID, /reopen ID.
- Telegram Web App панели оператора: https://uvmall-telegram-ai-admin.onrender.com/operator. Сам адрес доступен, но обращения и действия доступны **только при запуске кнопкой /panel из аккаунта менеджера**: сервер проверяет официальную HMAC-подпись Telegram и точный Telegram ID.
- Обращения покупателей о помощи, оптовые заявки и их статусы: новая, в работе, решена, закрыта. Повторные идентичные обращения с одним ключом не создают дубликаты.
- Безопасная обработка отправки: клиенту обещается доставка менеджеру только после подтверждения Telegram; менеджеру показывается номер заявки; отправить ответ клиенту можно из панели или командой /reply.
- Минимизация данных: запись включает Telegram ID, текст краткого запроса, тип и статус. Пароли, коды и данные карт не следует передавать боту. Статус сайта и ИИ: /health.
- Отдельная автоматическая проверка доступности uvmall.ru и бота запущена в ChatGPT, каждый час; уведомления только при изменениях.

## Ограничения, которые нельзя скрывать

**База сейчас временная.** Render Free не предоставляет постоянное файловое хранилище. По умолчанию SQLite находится в /tmp/uvmall-ai-tickets.sqlite3 и может исчезнуть после перезапуска/пересоздания контейнера. Уведомления о заявках остаются в истории Telegram менеджера, но восстановление точных статусов из сообщений пока не реализовано. Для надёжного производственного хранения требуется выделенная БД или устойчивый диск. Перенос файла в /var/data без подключённого диска не гарантирует долговечность.

**Каталог не синхронизирован.** Не задан CATALOG_FEED_URL, и поиск показывает 0 товаров. Для автоматической загрузки нужен серверный экспорт/API сайта по формату CATALOG_CONTRACT.md.

**uvmall.ru возвращал HTTP 503 при внешних проверках.** Работоспособность домена зависит от хостинга основного маркетплейса; сервер Telegram-бота на Render — отдельный и продолжает работать. Источник HTTP 503 не диагностирован без панели/логов основного хостинга.

**Telegram Business и командная панель.** Подключение автоматических ответов от имени @UVMALL19 требует назначения бота в «Автоматизации чатов» Telegram владельцем. Панель менеджера работает в отдельном чате с @uv_mallbot.

**Перевыпуск ключей.** Ранее Telegram Bot Token и ключ GigaChat передавались через переписку. Их необходимо перевыпустить у поставщиков и обновить только в секретах Render. Не размещайте токены в GitHub или сообщениях.

**Правовые настройки.** Политика обработки персональных данных и реквизиты оператора UVMALL не подтверждены. Перед масштабированием сбора заявок юридически оформите политику, согласие и сроки хранения. Бот не принимает платежи.

## Открыть операторскую панель

1. В Telegram войдите под аккаунтом, Telegram ID которого — 8771756849.
2. Откройте @uv_mallbot и в чате введите /panel.
3. Нажмите «Открыть панель UVMALL AI».
4. При появлении заявок выберите «Ответить», «В работу», «Решено» или «Закрыть».

В браузере вне Telegram панель покажет инструкцию входа; доступ к API без подписи Telegram отклоняется.

## Контроль состояния

Публичная техническая страница: https://uvmall-telegram-ai-admin.onrender.com/health

Записи operator_panel_enabled и tickets_storage показывают доступность панели и тип хранилища. Для проверки входа в чужой аккаунт использовать только проверенную подпись Telegram. Для проверки POST /api/operator/list без initData сервер должен возвращать HTTP 403.

Ещё есть технические команды /help и /site.

## Новая диагностика Telegram webhook

В следующем релизе endpoint `/health` дополнительно возвращает три безопасных поля:

- `telegram_webhook_status`: `registered` — Telegram подтвердил установку webhook; `token_missing`, `webhook_configuration_missing`, `bot_identity_mismatch`, `registration_failed` или `pending` — этап подключения, который требует внимания.
- `telegram_webhook_registered_at`: время последней подтверждённой установки webhook по Unix, либо `null`, если установка ещё не подтверждена.
- `telegram_menu_button_status`: `configured` — API Telegram принял настройку кнопки открытия `https://uvmall.ru/`; `failed` или `pending` — кнопка не подтверждена.

`status=online` означает только доступность HTTP-сервера, **не** гарантирует ответы в Telegram, доставку клиенту или успешную работу UVMALL. Внешние проверки допускают сетевые ошибки, поэтому их нельзя приравнивать к глобальному отключению сайта.

При временном сбое Telegram API подключение автоматически повторяется до четырёх раз, с паузами 15, 60 и 180 секунд. При отсутствии токена, некорректной конфигурации или несовпадении Telegram-бота попытки прекращаются для безопасной проверки настроек.

Изменения подготовлены в отдельном pull request и не показывают фактическое состояние production, пока обновление не развёрнуто в подтверждённом Render workspace. Перед развёртыванием необходимо проверить тесты CI, а после — `/health`, `/start`, `/site`, `/help` и кнопку меню в реальном Telegram. Секреты не публиковать.

## Ближайшие условия полноценного запуска

1. Доступ к хостингу основного uvmall.ru для устранения HTTP 503.
2. Защищённый read-only экспорт реальных опубликованных товаров из uvmall.ru.
3. Отдельная постоянная БД для заявок и истории статусов (без использования сторонних несвязанных проектов).
4. Проверка обработки персональных данных и замена скомпрометированных ключей.

## Улучшение версии 3.3: диагностика и анонимная аналитика

- Команда **/status** проверяет из сети Render основной uvmall.ru и кабинет seller.uvmall.ru. Она отображает фактический код или сетевую ошибку и не утверждает, что сайт недоступен для всех пользователей.
- В панели оператора видны суммарные поиски, запросы без результатов, открытия справки и оптовые заявки за 7 дней — без хранения поисковых фраз, IP-адресов или персональных предпочтений.
- Для закрытых и решённых обращений реализовано автоматическое удаление через 90 дней при запуске сервиса. Активные обращения сохраняются, но на Render Free всё хранилище остаётся временным.
- Отправка обычных сообщений пользователям по /reply возможна лишь если Telegram разрешает боту писать в их чат; при отказе менеджер получает явную ошибку.
